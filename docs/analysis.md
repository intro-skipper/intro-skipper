# Analysis

How library changes become analysis passes, how a pass decides what to analyze, and what it records. Terms such as season key, pass, feeder and quiet period are defined in `CONTEXT.md`. Credits detection is in `docs/credits.md`, and where results are stored is in `docs/segments.md`.

## The analysis queue

`AnalysisScheduler` runs every pass, one at a time, on one worker. Each feeder enqueues a request and gets a handle that completes with the pass that covered it, is cancelled when shutdown drops it, and faults when the pass threw. Pending requests are dropped on shutdown.

- **Changed items.** The library watcher (`Entrypoint`) queues the ids of changed episodes and movies. They run together once `AnalysisScheduler.QuietPeriod` has passed since the most recent change. The window slides on every change and is measured from the change, so an item that waited behind a running pass runs as soon as that pass ends. Seasons are resolved when the pass starts, so no library query runs on Jellyfin's event thread. The watcher also deletes the fingerprint cache of removed items.
- **Manual scan.** A dashboard scan runs as its own pass, erase then analyze, ahead of any pending library pass, and is always accepted. Nothing absorbs it. A scan for a key that is already pending joins it. One requested while that key's scan runs queues a follow-up pass, because the running pass may already have taken its inventory. The season is resolved when the pass starts, so a season that changed while the scan waited is erased and analyzed as it is, and a key that no longer resolves completes without running. The erase goes through the same `ISegmentEraser` as the dashboard's erase endpoints and keeps user segments, so the scan analyzes only the modes they do not settle. A failed erase faults the scan instead of analyzing over records that were never cleared. A season whose analysis fails, or a series that fails to resolve, faults the scan too, once its other seasons have run. A manual scan analyzes Season 0 even while `AnalyzeSeasonZero` is off; library and changed-items passes skip an opted-out Season 0.
- **Library pass.** `DetectSegmentsTask` requests a pass over every enabled library and waits for it. The pass starts once the worker is free and every pending manual scan has run, and it never cancels a running pass; only the task's own token or shutdown cancels one. It covers no pending request: changed items still run in their own pass, which is cheap when the library pass already analyzed them, so a cancelled or failed library pass drops no pending request. The library request itself is not requeued; seasons the pass did not reach wait for the next one. Cancelling the task withdraws a waiting request, or cancels the running library pass and returns once it has stopped, so Jellyfin's task list and the dashboard agree.
- **Dashboard state.** `AnalysisSchedulerStatus.IsRunning` is true while a pass runs or a manual scan or library pass is pending. A changed item waiting out its quiet period does not count, so a library change never locks the scan button. The dashboard polls its season's `ScanStatus` until that scan has run. The queue keeps each completed manual scan's outcome per key, so a failed scan reports as failed until a follow-up succeeds.

## Seasons

`SeasonResolver` turns library items into the seasons the analyzers work on, one series at a time, by Jellyfin's own definition: the series' episodes, fetched through the series and grouped by their season id. A series stored flat in its folder resolves like one with season folders. Virtual episodes are shown but never analyzed, and items without a path are logged and skipped.

- **In-season specials.** A special stored in Season 0 that airs within another season joins its host season when that season resolves with episodes of its own, and otherwise stays in Specials.
- **Unattached items.** An episode Jellyfin has not attached to a season yet joins the season its numbered siblings resolved to, or waits for the series refresh that attaches it, which queues it again. An item Jellyfin has not probed yet waits the same way.
- **Scope.** A library pass resolves one series at a time and spreads its seasons over `MaxParallelism` slots. A scoped pass resolves only the series that own the requested items (`OwnersOf`) and analyzes the seasons that are, or hold, one of them. A library pass logs a season or series that fails and goes on. A scoped pass also goes on, then throws once its seasons have run, so its handles fault. An id in a library the plugin is disabled for is unknown to every path.
- **Dashboard.** The dashboard resolves a season on demand (`ResolveDisplayed`) by Jellyfin's own season view rule. Its episode list shows every episode Jellyfin shows under the season: in-season specials appear under Specials, and under their host season too when Jellyfin's `DisplaySpecialsWithinSeasons` setting is on. Erase and scan act on the listed episodes that are eligible for analysis, and the scan analyzes the seasons they are analyzed in. An id the server does not know, a season outside an enabled library, or a series id that does not match answers 404.

## A season's pass

`BaseItemAnalyzerTask` takes each resolved season through these steps, then runs every mode over it. The pass never writes to Jellyfin: every segment write journals its item, and the projection worker converges the mirror.

1. **Verify.** `VerifyQueueAsync` fetches each episode from the server again, so one removed or re-imported after its series resolved is skipped. It drops episodes that are missing on disk or excluded under the live configuration, then `QueueVerifier` classifies the rest against the stored analysis records.
2. **Reset replaced files.** Episodes whose file changed lose their automatic segments, subtitle rows included, and their fingerprint cache through `ResetItemsForReanalysisAsync`, then analyze like new ones. Rows timed against the old file are no fallback for the new one. A change that Jellyfin's own refresh notices never reaches this step, because `SegmentProvider.CleanupExtractedData` has already deleted the episode's records and fingerprint cache.
3. **Clear derived previews.** When Preview scanning is off or the season's previews do not derive from the credits end, `ClearCreditsDerivedPreviewsAsync` deletes the previews an earlier pass derived for verified episodes, even if queue verification finds no analyzer work. It also clears those items' Preview analysis records so a later Preview pass can regenerate its result. User segments and chapter previews stay, and excluded episodes keep their previews.
4. **Reanalyze settled seasons.** With `ReanalyzeSettledSeasons` on, a season that has stopped receiving episodes is analyzed once more against its complete episode set. That means at least `SeasonReanalysisPlanner.MinimumEpisodes` episodes, not a movie, not an opted-out Season 0, and a newest episode older than `SettledSeasonDelayHours`. Only modes whose recorded episode set differs from the current one are reset. A Credits reset never reopens Preview. Automatic Credits rows stay as fallbacks until the per-episode result replaces, clears or retains them, so a failed keyframe scan does not blank the previous result. When Preview scanning is enabled, credits-derived previews are refreshed after the mode passes complete for episodes whose Credits result settled, including seasons where Credits or Preview has no analyzer work to run. When Preview scanning is off, step 3 clears those previews and settled-season resets do not recreate them. An unreadable or failed episode with retained automatic Credits rows sharing one hash can derive its Preview under that hash when no higher-priority Preview takes precedence. Settled results, including user-provided Credits, use the current Credits hash. Chapter and subtitle previews do not depend on credits. This reset keeps the subtitle rows of each reset mode that has subtitle detection active and that the season does not skip. The file is unchanged, so they stay as the fallback until the subtitle pass replaces or retires them. A mode's episode set is recorded only after its analysis completes (`RecordSettleReanalysisAsync`), so the modes a failed or cancelled pass left unfinished are reset again on the next pass.
5. **Read chapters.** Before any mode runs, `BaseItemAnalyzerTask` reads each episode's chapters into `QueuedEpisode.Chapters` from the chapter source: Jellyfin's chapter table, or with `UseEmbeddedChaptersForAnalysis` the chapters embedded in the media file, one ffprobe per episode (`IFFmpegService.GetEmbeddedChaptersAsync`), so chapters another plugin added to Jellyfin's table play no part. The embedded read shapes the chapters as Jellyfin's own probe stores them (`FFmpegOutputParser.ParseChapters`): starts rounded to the millisecond, untitled chapters named in the server's language, chapters at or past the runtime dropped. For a file no other plugin touched, both sources therefore hold the same list, except a chapter with a negative start, which Jellyfin keeps and the parser drops. It reads only when some mode will run an analyzer over the season: an episode is open in a mode whose action is not None, and the season is not an opted-out Season 0 outside a manual scan. A settled season therefore costs no probe. An episode whose embedded chapters ffprobe cannot read sits out the analyzer modes: none analyzes or records a result for it, and it is no Chromaprint reference for its siblings. It keeps the rows the earlier steps left, except, when Preview scanning is enabled, a completed settled-season Credits reset may refresh or create a derived Preview from its retained automatic Credits rows when those rows share one stored hash and no higher-priority Preview takes precedence. That Preview uses the retained hash. With Preview scanning off, step 3 clears credits-derived previews instead. With no mode analysis record, the episode is retried on the next pass. The settled-season record still covers it, so one failed read does not reset the season again. A failed read of Jellyfin's chapter table fails the season. Each episode remembers which source its chapters came from (`QueuedEpisode.ChaptersSource`), and the modes hash that source rather than the live setting, so a setting changed while the pass runs is caught by the chapter source check on the next pass instead of recording chapters from one source under the other's hash.
   - **Chapter source check.** An episode whose records the verifier settled under the other source's hash (`QueuedEpisode.ChapterSourceChecks`) has its chapters read from both sources, the table and the file, before anything else. When the two lists are the same, the analyzers would get the same input from either, so the records and their segments are re-stamped with the current hash (`UpgradeAnalysisHashAsync`), the episode stays settled, and later passes read nothing for it. When they differ, or the setting is off and ffprobe cannot read the file, the checked modes reopen and the episode is analyzed again. With the setting on, an unreadable file sits the episode out as described above, check included, and the next pass checks it again. A switch of the setting therefore costs one ffprobe per recorded episode on the next pass, and reruns the episodes whose two sources differ: a table another plugin changed, Jellyfin's placeholder chapters (its dummy chapter setting), untitled chapters Jellyfin named under another server language, or a table a Jellyfin before 10.11 filled with chapters at or past the runtime. A user segment settles a mode whatever its record says, so such a record is neither checked nor probed. A record written with Chromaprint available still settles while the ffmpeg capability probe fails, but is not checked until a pass with Chromaprint: the check could reopen the mode, and without Chromaprint the chain could not reproduce the result it would discard. The pass logs per season how many episodes kept their analysis and how many rerun.
6. **Run each mode.** Every chapter read in this step uses the chapters of step 5: the chapter analyzer, chapter-boundary snapping, the subtitle recap end and the legacy black-frame chapter markers.
   - Introduction and Recap run a first-wins chain: the chapter analyzer, then Chromaprint when ffmpeg is compatible and the item is not a movie. Each analyzer skips the episodes an earlier one settled. Chromaprint still compares settled siblings, but re-derives only those with no active row for the mode from another source, so a sibling another analyzer settled keeps its rows. A write that admission or a higher-ranked row refuses leaves the episode to the next analyzer. A per-season `AnalyzerAction` of Chapter or Chromaprint, or the `PreferChromaprint` setting, moves that analyzer to the front. During settled-season reanalysis, when `UseSettledSeasonChromaprintConsensus` is on, each season-selected Introduction Chromaprint candidate range must have its own connected local group linked by matches no more than two successfully fingerprinted positions apart in season-number order. A group normally must span the configured number of distinct episodes, capped at the number with usable fingerprints but never below two; fewer than two usable fingerprints cannot confirm a range. If multiple pattern groups have at least half as many episodes as the largest group, the target adapts to the smallest of those comparable groups, allowing mid-season theme changes without letting an isolated small match lower the target. A single group may also qualify below the target when it covers at least three quarters of the usable fingerprints, so one divergent episode does not erase an otherwise strong consensus. Within one episode, ranges whose intersection covers at least 80% of the longer range are coalesced, allowing small endpoint differences from pairwise comparisons without joining substantially different ranges. Missing fingerprints do not consume positions. The same consensus applies to retries while the recorded settled episode set is current and the mode still has unresolved episodes. Turning the option off keeps ordinary season-wide Chromaprint pair matching.
   - A Chromaprint recap is built around a sting, the earliest audio that two episodes of the season share in the recap window (`RecapDetectionHelper.BuildRecapFromSting`). It runs from 0:00, or with `AnchorRecapToColdOpen` from the fade before the sting, to the start of the first black run of at least 2 s that starts after the sting and after `MinimumRecapDetectionDuration`. The run must start before the earliest intro and before `MaximumRecapDetectionDuration` (`RecapDetectionHelper.GetMaximumBoundaryAsync`), the range the recap black-frame scan covers. Without such a run the sting gives no recap. A sting must last at least 4 s and be shared with at least two other episodes of the compared set (one when the set has only two), because a chance match of one pair is usually a studio logo. In a set of five or more episodes, a sting every episode shares is a logo or an opening theme, so it gives no recap (`ChromaprintAnalyzer.FilterRecapBySeasonSupport`). The recap comparison therefore meets every pair instead of stopping at the first match. The latest black frame in that range often lies in a dark cold open or a network card after the recap, so it is no end for a sting. The `DetectRecapUsingBlackFrames` fallback has no sting and still ends its recap from 0:00 at the latest black frame.
   - Commercial uses chapters only, and the chapter analyzer emits every matching commercial chapter. The other modes take a single chapter match.
   - Credits runs `CreditsPass`, which combines every analyzer's candidate per episode (`docs/credits.md`).
   - Preview uses chapters, and can derive a preview from the credits end (`AnimePreviewDeriver`, `docs/credits.md`). A season's `PreviewFromCreditsEnd` override decides that; without one, previews derive for anime when `AnimePreviewFromCreditsEnd` is on. If Credits failed and its automatic rows remain as fallbacks, a Preview-mode derive uses their stored Credits hash, provided those rows share one hash.
   - Recap and Preview run the chapter analyzer before subtitle matching, so chapter matches take precedence. Subtitle matching is an opt-in fallback before the remaining default analyzers (see Subtitle analysis below).
   - `AnalyzerAction.None` skips the mode for the season and records its episodes as analyzed under a hash that includes the action, so the season is not queued again on every pass.
   - `tools/CreditsRunner` in intro mode runs the default Introduction chain over labeled real files, one season at a time, and judges every Chapter, Chromaprint or time adjustment change to Introduction; its README has the commands.

A season key can override `AnalysisPercent`, `AnalysisLengthLimit`, `PreviewFromCreditsEnd`, `SubtitleRecapDetection` and `SubtitlePreviewDetection` (`DbSeasonAnalysisOverride`); a null value inherits the plugin-wide setting. The dashboard's Full Series option writes the same overrides to every season the series has at that moment, so a season added later inherits the plugin-wide settings.

### Subtitle analysis

A season's `SubtitleRecapDetection` and `SubtitlePreviewDetection` overrides, inheriting `EnableSubtitleRecapDetection` and `EnableSubtitlePreviewDetection` (both off by default), detect Recap and Preview from text subtitle cues that match `SubtitleRecapPattern` or `SubtitlePreviewPattern`, ignoring case. A pattern sees the cue text with markup removed and whitespace collapsed, so a multi-line cue reads as one line and `^` anchors to the start of the cue. The default recap pattern matches English, German, Spanish, French, Portuguese, Italian, Dutch, Japanese, Chinese and Korean recap wordings. Its German, Spanish, French, Portuguese, Dutch and Japanese forms must open the cue, because a title card is a whole cue and some of those words also occur in dialogue. The Korean form follows the title, so it must close the cue. Detection is active for a mode while its effective option is on and its pattern is not blank. `PluginConfiguration.ActiveSubtitlePattern` alone decides that, for the analysis hash, the recorded file version, the queue verifier, the analyzer chain and the subtitle analyzer.

- **Extraction.** `IFFmpegService.ExtractSubtitleCuesAsync` converts the episode's embedded text subtitle streams and its text sidecars (`SubtitleSidecarFiles`) to WebVTT. A sidecar is a file named like the media file plus dot-separated segments, next to the media file or in the item's internal metadata folder (`QueuedEpisode.InternalMetadataPath`), where Jellyfin saves downloaded subtitles when the library does not save them with the media. The sidecar extensions read are `.srt`, `.ass`, `.ssa`, `.vtt`, `.sub`, `.smi` and `.sami`. An embedded stream qualifies only when jellyfin-ffmpeg 7.1.3 and 8.1.2 both decode its codec to text, which leaves out image subtitles. `SubtitleSidecarFiles` skips VobSub sidecars (a `.sub` next to an `.idx` in the same folder) for the same reason. An ffmpeg run demuxes each input until every output of it has stopped, so the selected embedded streams and the sidecars share one run, with one output file per stream. One run per stream would read a file with 40 text tracks 40 times, and a run per sidecar costs a process start each. ffmpeg opens every input before it creates an output and exits when it cannot open one, such as an empty or garbled sidecar. A failed run that wrote no output therefore runs again one input at a time, so that sidecar fails only itself. A sidecar that cannot be read is left out of the run. The files go to a new directory under Jellyfin's temp directory, which the scan deletes when it ends. A directory it cannot delete is logged and left for Jellyfin's Clean Cache Directory task.
- **Windows.** The analyzer passes the window its mode's cue must start in: the recap window (`QueuedEpisode.GetFingerprintRange`) for Recap, and the last `MaximumPreviewDuration` seconds for Preview. The run reads the media file only around it. When the window starts more than 10 s into the file, the run seeks to 10 s before it with `-copyts -start_at_zero -ss`, which keeps the cue times a full read gives, also on a file whose clock does not start at zero. When the window ends more than 5 s before the episode's duration, the read stops after it. A Matroska file read from its start goes through an ffconcat list whose `outpoint` is 15 s past the window on the file's own clock, the start time ffprobe reports plus that second, and the concat demuxer stops the file at the first packet of any stream past it. The 15 s cover a cue a muxer stored after the audio and video of its time, as ffmpeg does for up to 10 s with a sparse stream; a cue stored later than that, or a damaged packet with a timestamp far past its place, ends the read before the cue. The run reads the list with `-copyts`, because ffmpeg 8.1 otherwise subtracts a start time the concat demuxer derives from the packets, which counts an audio codec delay that a plain read leaves out, and with `-auto_convert 0`, because the concat demuxer otherwise puts every H.264 packet through `h264_mp4toannexb`, which ends the read at a damaged video packet while ffmpeg still exits 0. A file whose start time ffprobe cannot tell, such as one with only an unreadable video track, keeps the plain read. Any other read stops each output 5 s after the window with an output `-t`, which ends only once its stream delivers a cue past the stop time, so a sparse track can keep the run reading to the end of the file. MP4 keeps the output `-t`: its demuxer skips the samples of streams nobody reads, and through the concat demuxer it reads them all. An input `-t` would not stop decoded subtitle streams, and `-sseof` shifts every cue when the tail it asks for is longer than the file. Inside the window the cues equal a full read's, so the window adds nothing to the analysis hash. Sidecars are read whole, and `-copyts -start_at_zero` leaves their cue times as they are.
- **Charsets.** ffmpeg reads text subtitles as UTF-8 and drops every cue of a sidecar in another charset, while the run still succeeds. A sidecar that is valid UTF-8 or starts with a UTF-16 byte order mark goes to ffmpeg as is. Any other is decoded with the charset UtfUnknown detects, the detector Jellyfin uses, with ISO-8859-1 read as its superset Windows-1252 and Windows-1252 when nothing is detected, and ffmpeg reads a UTF-8 copy in the scan's directory instead. ffmpeg's `-sub_charenc` is not used: iconv rejects some charset names the detector reports, and a wrong guess would garble a UTF-8 file. A sidecar larger than the episode's cap goes to ffmpeg as is rather than into memory. The plugin compiles against UTF.Unknown 2.7.0, the version the server ships, and uses the server's copy at runtime.
- **Limits.** The episode's cap (`SubtitleEpisodeMaximumBytes`) is split evenly across the outputs, and ffmpeg's `-fs` stops each output at its share. A failed probe or run, a file operation that fails (listing or reading the sidecars, creating the output directory, reading an output), or an output that reached its share, leaves the scan incomplete (`SubtitleScan.Complete`). Outputs under their share are still matched after a failed run, though a crash, a timeout or a log over its cap cuts them off where the run stopped. A run that fails after writing output does not run again, and the media file's streams are never read one at a time.
- **Languages.** `SubtitleLanguages` lists the languages Recap and Preview detection read, and the default, empty, reads every language. The selection does not follow the audio language, because a recap's title card is often subtitled only in the translation tracks, and its narrated "previously on", if it is subtitled at all, only in the track of the audio language. A selection of only the audio language can therefore miss the recap. `SubtitleLanguageSelection` treats the ISO 639-1, 639-2/B and 639-2/T codes of a language (`de`, `ger`, `deu`) as the same language, whichever the setting or the file uses. Norwegian Bokmål and Nynorsk (`nb`, `nn`) count as Norwegian (`no`, `nor`), the tag files usually carry. A code with a region (`pt-BR`) compares by its language part, and a code .NET does not know matches only itself, ignoring case.
  - An embedded stream is read when its language tag names a selected language. An untagged or `und` stream is always read.
  - A sidecar's language comes from the dot-separated segments between the media file's name and the extension (`Episode.de.srt`, `Episode.ger.forced.ass`, `Episode.German.srt`). A segment names a language by one of its codes, or by its English or native name as .NET spells it (German, Deutsch); a segment that is a code of one language and a name of another counts as the code. A sidecar is read when any segment names a selected language, or when no segment names a known language. `hi` is Hindi and also the usual hearing-impaired flag, so `Episode.en.hi.srt` is read when English or Hindi is selected.
- **Recap.** The first matching cue that starts inside the window Chromaprint searches for recaps (`QueuedEpisode.GetFingerprintRange`) starts the recap, so a matching line of dialogue later in the episode never becomes one. The recap ends between `MinimumRecapDuration` and `MaximumRecapDuration` after the cue, and no later than the start of an active Introduction that follows the cue. Inside that range it ends at the first chapter start, or else at the start of the first black run of at least 2 s. The intro start is no end of its own, because a cold open often plays between the recap and the intro. Black runs come from the adaptive black-frame scan Chromaprint and black-frame recaps use (`RecapDetectionHelper.DetectAdaptiveBlackFramesAsync`), over the same range (`RecapDetectionHelper.GetMaximumBoundaryAsync`), so the detection cache serves all of them from one decode. A run is a sequence of consecutive black frames, and lasts through the start of the frame after its last. A recap that would end after that range, such as one whose cue follows the intro, can end only at a chapter. With neither, the match has no end. The analysis hash carries a token for this rule (`ConfigHasher`), so changing it reruns subtitle analysis alone in the seasons that detect subtitle recaps.
- **Preview.** The analyzer tries matching cues from the last one back, among those that start in the last `MaximumPreviewDuration` seconds. A preview runs from its cue to the end of the episode and must fit `MinimumPreviewDuration` and `MaximumPreviewDuration`.
- **Precedence.** Chapters run before subtitle matching and settle the episode first, and so does Chromaprint when the season prefers it. A subtitle match can then settle an episode before the remaining analyzers run. A row left by an earlier configuration ranks below every analyzer, so it never blocks the current pass (`docs/segments.md`). A credits-derived preview remains a fallback.
- **Outcomes.** The subtitle analyzer leaves a `SubtitleOutcome` per episode, and once every analyzer has run, the chain settles the mode from it:
  - The analyzer writes a match from a complete scan, which settles the episode. It writes a match from an incomplete scan too, but the mode stays open for the next pass, since an unread source can hold a better cue.
  - After a complete scan without a match, the analyzer deletes the episode's subtitle row of the mode (`ClearSubtitleSegmentsAsync`), and the other analyzers decide the mode.
  - An incomplete scan without a match is unresolved, and so is every pending episode when the pattern is not a valid .NET regular expression. Standing rows stay as the fallback, and the chain marks the mode failed, so every pass retries it until the scan completes or the pattern is fixed.
  - A match that admission rejects, because of a tombstone or a user segment, a match a current chapter row outranks, and a recap with no end leave the standing rows and settle the mode, since a retry would end the same way.
- **Stale rows.** The stale-row cleanup (`CleanStaleAutomaticSegmentsAsync`) covers only the episodes the pass analyzes for the mode, so an episode an earlier pass settled keeps its rows when a sibling reopens the mode, including the rows a subtitle-only pass kept under their old hash. With subtitle detection active, the cleanup runs after the chain instead of before it and skips the unresolved, rejected and failed episodes, so their old rows stay as the fallback. Credits cleanup also runs after the pass and preserves rows for failed episodes, allowing a failed keyframe scan to inspect and retain prior credits written under an older hash.
- **Sidecar changes.** Adding, rewriting or removing a text sidecar that extraction reads reopens only the modes with active subtitle detection, with no media reset and no fingerprint-cache wipe, as long as another record of the item confirms the media version (see Subtitle file version under Analysis records). A sidecar in a language the setting leaves out reopens nothing.
- **Subtitle-only reanalysis.** When only what subtitle detection reads changed, a subtitle setting or a sidecar of an unchanged media file, the mode reruns the subtitle analyzer alone (`QueuedEpisode.NeedsSubtitleOnlyReanalysis`). A chapter result, or a Chromaprint result the season prefers, outranks any subtitle match, so the episode keeps it without a scan. An episode whose standing result came from subtitles gets the full chain instead, since the analyzers ranked below subtitles never ran for it.
- **Derived previews.** When subtitle Preview detection is active and `ScanPreview` is on, the derive after the credits pass leaves every Preview state alone, so the Preview pass still runs the subtitle analyzer on those episodes.

## Analysis records

`AnalyzedItems` holds one row per item and mode, `(ItemId, Type, ConfigHash, FileVersion)`, recording that the item was analyzed under a configuration hash, whether or not it found segments. `QueueVerifier` settles an item whose record matches the current hash (`EpisodeState.Analyzed` with segments, `EpisodeState.NoSegments` without), and user segments always settle it. Anything else stays open, and deleting the record reopens the item. Every record change is one statement, for example in `MarkItemsAnalyzedAsync`, `EraseItemsAsync`, `ResetItemsForReanalysisAsync`, `DeleteSegmentsByModeAsync`, `UpgradeAnalysisHashAsync` and `BackfillFileVersionsAsync`. `SeasonStates` keeps only the analyzer action and the settled-reanalysis episode set per season and mode.

- **Configuration hash.** `ConfigHasher.Analysis` hashes the settings that affect one mode's output under the season's action, so the expected hash depends on the action and the mode, not the episode. Chromaprint availability is part of the hash for Chromaprint-capable modes, so a season settled with no segments is analyzed again once Chromaprint becomes available. A mode's subtitle pattern joins its hash only while that mode's subtitle detection is active, so with subtitle detection off, the subtitle settings change neither hash, and editing a pattern whose detection is off reopens nothing. A blank pattern detects nothing and hashes as detection off. The selected subtitle languages join the same token as sorted 639-2/T codes (`SubtitleLanguageSelection.Normalized`), so writing `ger` for `deu` reopens nothing. The subtitle settings form a separate part of a compound hash, so `QueueVerifier` can tell a subtitle-only change from a change to the other settings (`ConfigHasher.IsSubtitleOnlyHashChange`). The Preview hash of a season that derives previews from the credits end also carries a token for the derivation rule (`docs/credits.md`). Every Recap hash carries a token for the Chromaprint recap end rule, so a change to that rule reruns Recap once in every season, from the cached fingerprints and black-frame scans. While a preferred audio language is set under `PreferAudioStreamWithMostChannels`, the Chromaprint-backed modes carry a token for the stream ranking, which puts the default-disposition stream first as ffmpeg does. Seasons fingerprinted under the older channels-only ranking rerun once, and without a preferred language the token is absent. While `UseEmbeddedChaptersForAnalysis` is on, every mode's hash carries a chapter source token under every action, and with the setting off the token is absent, so the default configuration keeps its hashes. The token names the source a record was computed from. A switch alone reruns nothing: `QueueVerifier` settles a record that matches the hash of the other source and flags it for the chapter source check of the pass (step 5 above), which reopens the mode only when the two sources hold different chapters. The token sits outside the subtitle part, so a switch is never a subtitle-only change. A downgrade to a release without the token reruns every record written while the setting was on.
- **File version.** Chromaprint compares episodes across a season, so the plugin cannot analyze one file at a time inside Jellyfin's metadata refresh, and Jellyfin's library events cannot say whether a media file was replaced. Each record therefore stores the file version, the write time Jellyfin held for the media file, in ticks. Verification compares it with every record the item has, whatever the mode, since a record of a disabled mode still proves the file changed. A mismatch flags `QueuedEpisode.FileChanged` and the pass resets the item, except on a Recap or Preview record (see Subtitle file version). The check runs on every pass, so a replacement is caught even when its event was missed. A record without a version is stamped with the media version seen, unless the file changed. An item without a media version cannot be compared and keeps every verdict, except on a Recap or Preview record that carries the sidecar version (see Subtitle file version).
- **Subtitle file version.** A mode with active subtitle detection records `QueuedEpisode.SubtitleFileVersion` instead: a hash of the media version and the names, lengths and write times of the text sidecars extraction reads (`SubtitleSidecarFiles.FileVersion`), or the media version when there are none. Verification lists each folder once per season pass (`SubtitleSidecarFiles.FolderListings`), keeps the files with a subtitle extension, and takes their lengths and write times from that listing, so a sidecar written after its folder was listed counts from the next pass. On NTFS a listing reports a hard-linked sidecar as last written through its folder, so one rewritten through another link counts once something opens it by the library path. VobSub sidecars and sidecars in a language the setting leaves out are never read and do not count. A rewritten sidecar changes what subtitle detection reads, not the media that the other modes and the fingerprints describe, and a record written before subtitle detection was turned on or off carries the other version. So a Recap or Preview record that does not carry the version its mode records now reopens only that mode, with no reset and no cache wipe, when another record of the item confirms the media version. The mode then reruns subtitle detection alone when the record's hash is current apart from the subtitle settings, and its full chain otherwise. The sidecar version cannot tell a sidecar edit from a replaced media file, so without such a record the episode is reset like any replaced file. In a library that scans only Recap and Preview, a sidecar edit can therefore cost a reset and a fingerprint-cache wipe. With the mode's subtitle detection off, a record whose hash still matches was written under today's settings, so a different version can only mean the media file was replaced, and the episode is reset. That holds for a mode the pass does not run too, whose hash is compared under the season's saved analyzer action. An item without a media version cannot show a replaced file, so a sidecar change there reopens the mode without a reset.
- **Exclusions.** A record survives the item being excluded, so an item excluded and then included again with a matching record stays settled. `ExcludedTimestamps/Clear` is the explicit reset.

## Detection cache

`DetectionCacheService` stores raw ffmpeg output in its own database, `introskipper-cache.db`, behind `DetectionCacheDatabase`. Rows are keyed by item, entry type (`CacheEntryType`), mode and the time range they cover, carry a configuration hash from `ConfigHasher.DetectionCache`, and are Brotli-compressed. The cache is an optimization: a failed write is logged and swallowed and never discards a valid analysis result, and when the database cannot open, reads miss and writes do nothing.

- **Invalidation.** A row is readable under its current hash, or when it carries no hash at all, so changing a setting the hash covers leaves the old hashed rows unread. A change to a row's format bumps the token for that entry type inside `ConfigHasher`. Rows no read path can accept are removed by `DeleteUnreadableEntriesAsync`. Nothing wipes the whole cache.
- **Fingerprints.** Chromaprint rows are scoped to the effective audio stream (`ConfigHasher.StreamScopedDetectionCacheHashPrefix`). Rows written before stream selection existed (`ConfigHasher.LegacyChromaprintCacheWithoutLanguage`) stay readable while the effective stream is ffmpeg's default, so analyzed episodes keep their place in the comparison pool. That hash input is frozen, and a pinned-hash test guards it.
- **Cleanup.** `CleanCacheTask` clears the segment, season-state and cache rows of items the server no longer knows, and deletes unreadable cache rows. Items that exist but were not resolved, such as those in a provider-disabled library or an episode waiting for its season, keep their segment and season-state rows. Only their unreadable cache rows go, since that sweep covers every item. When any library or series fails to resolve, the task skips the cleanup rather than act on an incomplete inventory.

## Upgrading from 10.11

`LegacyDatabaseImporter` turns the old per-season episode lists into analysis records under the season's hash, so upgrading does not rescan them. Old schemas that stored no season hash import with an empty hash, which settles nothing, so those seasons are analyzed again.

Before verification, `LegacyAnalysisCompatibility` recognizes the frozen analysis hashes of releases 1.10.11.22, 1.10.11.23 and 1.10.11.24 under the retained settings and season action. 10.11 hashed the plugin-wide values, so a season override that differs from them blocks adoption for the modes it affects: the analysis percentage or length limit for Introduction, and the derived-preview setting for Credits. It adopts matching completion records and matching active automatic segment hashes under the current hash in one transaction, without changing timestamps, segment ids, provenance, the settled-season episode sets or the detection cache. This covers records already imported into a 12.0 database and completed modes that found no segments. An adopted record carries the current hash and follows normal invalidation; missing or reset records and unrecognized or empty hashes are never adopted. Releases that did not record Chromaprint availability stay eligible for analysis rather than inventing that state.

Recap and Preview are never adopted, because 12.0 changed how both are detected and a 10.11 result under an older hash is not what the current settings produce. Adoption of Introduction and Credits requires the audio-selection settings introduced in 12.0 to keep their defaults, and the 12.0 credits legacy opt-in or chapter enhancement blocks Credits adoption. 10.11 read Jellyfin's chapter table, so an adopted record names that source; with `UseEmbeddedChaptersForAnalysis` on, the chapter source check decides per episode whether the file holds the same chapters. The pre-.24 formats omit the snapping-offset option, so enabling it blocks adoption from them. Credits hashes from .22 and .23 are never adopted: they omit the minimum shared-region duration, and today's defaults cannot prove the value those releases used. Those seasons stay eligible for analysis even when their settings are at the defaults, so lowering the credits minimum still takes effect. Introduction and Commercial stay eligible for adoption from the older formats. An adopted Credits record takes the hash the pass expects for its season, which carries the season's own derived-preview setting. 10.11 derived previews for anime only, so a season that does not derive them got the same credits from 10.11 whatever the plugin-wide setting was. Changes to settings in the 10.11 hash or to the season action still require analysis. The old Chromaprint-availability value is kept, so gaining Chromaprint still reopens a negative result while a failed capability probe does not discard a successful one. Both 1.10.11.24 credits analyzer choices are recognized. Adopted results keep their older detection behavior until an explicit rescan or another normal invalidation; adoption does not claim the newer algorithms produced them.
