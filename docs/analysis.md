# Analysis

How library changes become analysis passes, how a pass decides what to analyze, and what it records. Terms such as season key, pass, feeder and quiet period are defined in `CONTEXT.md`. Credits detection is in `docs/credits.md`, and where results are stored is in `docs/segments.md`.

## The analysis queue

`AnalysisScheduler` runs every pass, one at a time, on one worker. Each feeder enqueues a request and gets a handle that completes with the pass that covered it, is cancelled when shutdown drops it, and faults when the pass threw. Pending requests are dropped on shutdown.

- **Changed items.** The library watcher (`Entrypoint`) queues the ids of changed episodes and movies. They run together once `AnalysisScheduler.QuietPeriod` has passed since the most recent change. The window slides on every change and is measured from the change, so an item that waited behind a running pass runs as soon as that pass ends. Seasons are resolved when the pass starts, so no library query runs on Jellyfin's event thread. The watcher also deletes the fingerprint cache of removed items.
- **Manual scan.** A dashboard scan runs as its own pass, erase then analyze, ahead of any pending library pass, and is always accepted. Nothing absorbs it. A scan for a key that is already pending joins it. One requested while that key's scan runs queues a follow-up pass, because the running pass may already have taken its inventory. The season is resolved when the pass starts, so a season that changed while the scan waited is erased and analyzed as it is, and a key that no longer resolves completes without running. The erase goes through the same `ISegmentEraser` as the dashboard's erase endpoints, and a failed erase faults the scan instead of analyzing over records that were never cleared.
- **Library pass.** `DetectSegmentsTask` requests a pass over every enabled library and waits for it. The pass starts once the worker is free and every pending manual scan has run, and it never cancels a running pass; only the task's own token or shutdown cancels one. It covers no pending request: changed items still run in their own pass, which is cheap when the library pass already analyzed them, so a cancelled or failed library pass drops no pending request. The library request itself is not requeued; seasons the pass did not reach wait for the next one. Cancelling the task withdraws a waiting request, or cancels the running library pass and returns once it has stopped, so Jellyfin's task list and the dashboard agree.
- **Dashboard state.** `AnalysisSchedulerStatus.IsRunning` is true while a pass runs or a manual scan or library pass is pending. A changed item waiting out its quiet period does not count, so a library change never locks the scan button. The dashboard polls its season's `ScanStatus` until that scan has run. The queue keeps each completed manual scan's outcome per key, so a failed scan reports as failed until a follow-up succeeds.

## Seasons

`SeasonResolver` turns library items into the seasons the analyzers work on, one series at a time, by Jellyfin's own definition: the series' episodes, fetched through the series and grouped by their season id. A series stored flat in its folder resolves like one with season folders. Virtual episodes are shown but never analyzed, and items without a path are logged and skipped.

- **In-season specials.** A special stored in Season 0 that airs within another season joins its host season when that season resolves with episodes of its own, and otherwise stays in Specials.
- **Unattached items.** An episode Jellyfin has not attached to a season yet joins the season its numbered siblings resolved to, or waits for the series refresh that attaches it, which queues it again. An item Jellyfin has not probed yet waits the same way.
- **Scope.** A library pass resolves one series at a time and spreads its seasons over `MaxParallelism` slots. A scoped pass resolves only the series that own the requested items (`OwnersOf`) and analyzes the seasons that are, or hold, one of them. An id in a library the plugin is disabled for is unknown to every path.
- **Dashboard.** The dashboard resolves a season on demand (`ResolveDisplayed`) by Jellyfin's own season view rule. Its episode list shows every episode Jellyfin shows under the season: in-season specials appear under Specials, and under their host season too when Jellyfin's `DisplaySpecialsWithinSeasons` setting is on. Erase and scan act on the listed episodes that are eligible for analysis, and the scan analyzes the seasons they are analyzed in. An id the server does not know, a season outside an enabled library, or a series id that does not match answers 404.

## A season's pass

`BaseItemAnalyzerTask` takes each resolved season through these steps, then runs every mode over it. The pass never writes to Jellyfin: every segment write journals its item, and the projection worker converges the mirror.

1. **Verify.** `VerifyQueueAsync` fetches each episode from the server again, so one removed or re-imported after its series resolved is skipped. It drops episodes that are missing on disk or excluded under the live configuration, then `QueueVerifier` classifies the rest against the stored analysis records.
2. **Reset replaced files.** Episodes whose file changed lose their automatic segments, subtitle rows included, and their fingerprint cache through `ResetItemsForReanalysisAsync`, then analyze like new ones. Rows timed against the old file are no fallback for the new one.
3. **Clear derived previews.** When the season's previews do not derive from the credits end, `ClearCreditsDerivedPreviewsAsync` deletes the previews an earlier pass derived. User segments and chapter previews stay.
4. **Reanalyze settled seasons.** With `ReanalyzeSettledSeasons` on, a season that has stopped receiving episodes is analyzed once more against its complete episode set. That means at least `SeasonReanalysisPlanner.MinimumEpisodes` episodes, not a movie, not an opted-out Season 0, and a newest episode older than `SettledSeasonDelayHours`. Only modes whose recorded episode set differs from the current one are reset, and Preview joins a Credits reset when previews derive from the credits end. This reset keeps the subtitle rows of each reset mode that has subtitle detection active and that the season does not skip. That includes Preview when it joins a Credits reset, even with `ScanPreview` off. The file is unchanged, so they stay as the fallback until the subtitle pass replaces or retires them. A mode's episode set is recorded only after its analysis completes (`RecordSettleReanalysisAsync`), so the modes a failed or cancelled pass left unfinished are reset again on the next pass.
5. **Run each mode.**
   - Introduction and Recap run a first-wins chain: the chapter analyzer, then Chromaprint when ffmpeg is compatible and the item is not a movie. Each analyzer skips the episodes an earlier one settled. A per-season `AnalyzerAction` of Chapter or Chromaprint, or the `PreferChromaprint` setting, moves that analyzer to the front.
   - Commercial uses chapters only, and the chapter analyzer emits every matching commercial chapter. The other modes take a single chapter match.
   - Credits runs `CreditsPass`, which combines every analyzer's candidate per episode (`docs/credits.md`).
   - Preview uses chapters, and can derive a preview from the credits end (`AnimePreviewDeriver`, `docs/credits.md`). A season's `PreviewFromCreditsEnd` override decides that; without one, previews derive for anime when `AnimePreviewFromCreditsEnd` is on.
   - Recap and Preview run the chapter analyzer before subtitle matching, so chapter matches take precedence. Subtitle matching is an opt-in fallback before the remaining default analyzers (see Subtitle analysis below).
   - `AnalyzerAction.None` skips the mode for the season and records its episodes as analyzed under a hash that includes the action, so the season is not queued again on every pass.

A season key can override `AnalysisPercent`, `AnalysisLengthLimit` and `PreviewFromCreditsEnd` (`DbSeasonAnalysisOverride`); a null value inherits the plugin-wide setting.

### Subtitle analysis

`EnableSubtitleRecapDetection` and `EnableSubtitlePreviewDetection`, both off by default, detect Recap and Preview from text subtitle cues that match `SubtitleRecapPattern` or `SubtitlePreviewPattern`, ignoring case. A pattern sees the cue text with markup removed and whitespace collapsed, so a multi-line cue reads as one line and `^` anchors to the start of the cue. The default recap pattern matches English, German, Spanish, French, Portuguese, Italian and Dutch recap wordings. Its German, Spanish, French, Portuguese and Dutch forms must open the cue, because a title card is a whole cue and some of those words also occur in dialogue. Detection is active for a mode while its option is on and its pattern is not blank. `PluginConfiguration.ActiveSubtitlePattern` alone decides that, for the analyzer chain, the analysis hash, the file version and legacy adoption.

- **Extraction.** `IFFmpegService.ExtractSubtitleCuesAsync` converts the episode's embedded text subtitle streams and the text sidecars next to the media file (`SubtitleSidecarFiles`) to WebVTT in one FFmpeg extraction run, with one output file per source. An embedded stream qualifies only when jellyfin-ffmpeg 7.1.3 and 8.1.2 both decode its codec to text, which leaves out image subtitles. `SubtitleSidecarFiles` skips VobSub sidecars (a `.sub` next to an `.idx`) for the same reason. The files go to a new directory under Jellyfin's temp directory, which the scan deletes when it ends. A directory it cannot delete is logged and left for Jellyfin's Clean Cache Directory task.
- **Limits.** The episode's cap (`SubtitleEpisodeMaximumBytes`) is split evenly across the outputs, and ffmpeg's `-fs` stops each output at its share. A failed probe or run, a file operation that fails (listing the sidecars, creating the output directory, reading an output), or an output that reached its share, leaves the scan incomplete (`SubtitleScan.Complete`). Outputs under their share are still matched after a failed run, though a crash, a timeout or a log over its cap cuts them off where the run stopped. A failed embedded run is not retried one stream at a time.
- **Languages.** `SubtitleLanguages` lists the languages Recap and Preview detection read, and the default, empty, reads every language. The selection does not follow the audio language, because a recap's title card is often subtitled only in the translation tracks, and its narrated "previously on" only in the track of the audio language. `SubtitleLanguageSelection` treats the ISO 639-1, 639-2/B and 639-2/T codes of a language (`de`, `ger`, `deu`) as the same language, whichever the setting or the file uses. Norwegian Bokmål and Nynorsk (`nb`, `nn`) count as Norwegian (`no`, `nor`), the tag files usually carry. A code with a region (`pt-BR`) compares by its language part, and a code .NET does not know matches only itself, ignoring case.
  - An embedded stream is read when its language tag names a selected language. An untagged or `und` stream is always read.
  - A sidecar's language comes from the dot-separated segments between the media file's name and the extension (`Episode.de.srt`, `Episode.ger.forced.ass`). A sidecar is read when any segment names a selected language, or when no segment is a known language code. `hi` is Hindi and also the usual hearing-impaired flag, so `Episode.en.hi.srt` is read when English or Hindi is selected.
- **Recap.** The analyzer tries matching cues in time order, and only those that start inside the window Chromaprint searches for recaps (`QueuedEpisode.GetFingerprintRange`), so a matching line of dialogue later in the episode never becomes a recap. A recap that starts before the episode's first active Introduction ends at the intro's start. When the intro comes first, or the episode has none, the recap ends at the next chapter start after the cue, and with no such chapter the match has no end. When the recap is shorter than `MinimumRecapDuration` or longer than `MaximumRecapDuration`, the analyzer tries the next matching cue.
- **Preview.** The analyzer tries matching cues from the last one back. A preview runs from its cue to the end of the episode and must fit `MinimumPreviewDuration` and `MaximumPreviewDuration`.
- **Precedence.** Chapters run before subtitle matching and settle the episode first. A subtitle match can then settle an episode before the remaining analyzers run. A credits-derived preview remains a fallback (`docs/segments.md`).
- **Outcomes.** The subtitle analyzer tracks unresolved scans and admission-rejected candidates per episode, and once every analyzer has run, the chain settles the mode from those outcomes:
  - The analyzer writes a match from a complete scan, which settles the episode. It writes a match from an incomplete scan too, but the mode stays open for the next pass, since an unread source can hold a better cue.
  - After a complete scan without a match, the analyzer deletes the episode's subtitle row of the mode (`ClearSubtitleSegmentsAsync`), and the other analyzers decide the mode.
  - An incomplete scan without a match is unresolved, and so is every pending episode when the pattern is not a valid .NET regular expression. Standing rows stay as the fallback, and the chain marks the mode failed, so every pass retries it until the scan completes or the pattern is fixed.
  - A match that admission rejects because of a tombstone or a user segment leaves standing rows and settles the mode, since a retry would end the same way. A recap cue with no reliable end leaves standing rows and remains retryable for a later chapter marker.
- **Stale rows.** With subtitle detection active, the stale-row cleanup (`CleanStaleAutomaticSegmentsAsync`) runs after the chain instead of before it. It covers only the episodes the pass analyzed for the mode, and skips the unresolved, rejected and failed ones, so their old rows stay as the fallback. An episode an earlier pass settled keeps its rows when a sibling reopens the mode.
- **Sidecar changes.** Adding, rewriting or removing a text sidecar that extraction reads reopens only the modes with active subtitle detection, with no media reset and no fingerprint-cache wipe (see File version under Analysis records). A sidecar in a language the setting leaves out reopens nothing.
- **Derived previews.** When subtitle Preview detection is active and `ScanPreview` is on, the derive after the credits pass leaves every Preview state alone, so the Preview pass still runs the subtitle analyzer on those episodes.

## Analysis records

`AnalyzedItems` holds one row per item and mode, `(ItemId, Type, ConfigHash, FileVersion)`, recording that the item was analyzed under a configuration hash, whether or not it found segments. `QueueVerifier` settles an item whose record matches the current hash (`EpisodeState.Analyzed` with segments, `EpisodeState.NoSegments` without), and user segments always settle it. Anything else stays open, and deleting the record reopens the item. Every record change is one statement (`MarkItemsAnalyzedAsync`, `EraseItemsAsync`, `ResetItemsForReanalysisAsync`, `DeleteSegmentsByModeAsync`). `SeasonStates` keeps only the analyzer action and the settled-reanalysis episode set per season and mode.

- **Configuration hash.** `ConfigHasher.Analysis` hashes the settings that affect one mode's output under the season's action, so the expected hash depends on the action and the mode, not the episode. Chromaprint availability is part of the hash for Chromaprint-capable modes, so a season settled with no segments is analyzed again once Chromaprint becomes available. A mode's subtitle pattern joins its hash only while that mode's subtitle detection is active, so with subtitle detection off, Recap and Preview keep the hashes they had before the option existed, and editing a pattern whose detection is off reopens nothing. The selected subtitle languages join the same token as sorted 639-2/T codes (`SubtitleLanguageSelection.Normalized`), so writing `ger` for `deu` reopens nothing. An empty selection adds nothing, so the hash stays what it was before the setting existed. The Preview hash of a season that derives previews from the credits end also carries a token for the derivation rule (`docs/credits.md`).
- **File version.** Chromaprint compares episodes across a season, so the plugin cannot analyze one file at a time inside Jellyfin's metadata refresh, and Jellyfin's library events cannot say whether a media file was replaced. Each record therefore stores the file version, the write time Jellyfin held for the media file, in ticks. Verification compares it with every record the item has, whatever the mode, since a record of a disabled mode still proves the file changed. A mismatch flags `QueuedEpisode.FileChanged` and the pass resets the item, except on a Recap or Preview record (see Subtitle file version). The check runs on every pass, so a replacement is caught even when its event was missed. A record without a version is stamped with the media version seen, unless the file changed. An item without a media version cannot be compared and keeps every verdict, except on a Recap or Preview record that carries the sidecar version (see Subtitle file version).
- **Subtitle file version.** A mode with active subtitle detection records `QueuedEpisode.SubtitleFileVersion` instead: a hash of the media version and the names, lengths and write times of the text sidecars extraction reads (`SubtitleSidecarFiles.FileVersion`), or the media version when there are none. VobSub sidecars and sidecars in a language the setting leaves out are never read and do not count. A Recap or Preview record that does not carry the version its mode records now reopens only that mode, with no reset and no cache wipe. A rewritten sidecar changes what subtitle detection reads, not the media that the other modes and the fingerprints describe, and a record written before subtitle detection was turned on or off carries the other version. With the mode's subtitle detection off, a record whose hash still matches was written under today's settings, so a different version can only mean the media file was replaced, and the episode is reset like any other. That holds for a mode the pass does not run too, whose hash is compared under the season's saved analyzer action. Otherwise only the records of the other modes can show a replaced media file.
- **Exclusions.** A record survives the item being excluded, so an item excluded and then included again with a matching record stays settled. `ExcludedTimestamps/Clear` is the explicit reset.

## Detection cache

`DetectionCacheService` stores raw ffmpeg output in its own database, `introskipper-cache.db`, behind `DetectionCacheDatabase`. Rows are keyed by item, entry type (`CacheEntryType`), mode and the time range they cover, carry a configuration hash from `ConfigHasher.DetectionCache`, and are Brotli-compressed. The cache is an optimization: a failed write is logged and swallowed and never discards a valid analysis result, and when the database cannot open, reads miss and writes do nothing.

- **Invalidation.** A row is readable under its current hash, or when it carries no hash at all, so changing a setting the hash covers leaves the old hashed rows unread. A change to a row's format bumps the token for that entry type inside `ConfigHasher`. Rows no read path can accept are removed by `DeleteUnreadableEntriesAsync`. Nothing wipes the whole cache.
- **Fingerprints.** Chromaprint rows are scoped to the effective audio stream (`ConfigHasher.StreamScopedDetectionCacheHashPrefix`). Rows written before stream selection existed (`ConfigHasher.LegacyChromaprintCacheWithoutLanguage`) stay readable while the effective stream is ffmpeg's default, so analyzed episodes keep their place in the comparison pool. That hash input is frozen, and a pinned-hash test guards it.
- **Cleanup.** `CleanCacheTask` clears the segment, season-state and cache rows of items the server no longer knows, and deletes unreadable cache rows. Items that exist but were not resolved, such as those in a provider-disabled library or an episode waiting for its season, keep their segment and season-state rows. Only their unreadable cache rows go, since that sweep covers every item. When any library or series fails to resolve, the task skips the cleanup rather than act on an incomplete inventory.

## Upgrading from 10.11

`LegacyDatabaseImporter` turns the old per-season episode lists into analysis records under the season's hash, so upgrading does not rescan them. Old schemas that stored no season hash import with an empty hash, which settles nothing, so those seasons are analyzed again.

Before verification, `LegacyAnalysisCompatibility` recognizes the frozen analysis hashes of releases 1.10.11.22, 1.10.11.23 and 1.10.11.24 under the retained settings and season action, for seasons without analysis-window overrides. It adopts matching completion records and matching active automatic segment hashes under the current hash in one transaction, without changing timestamps, segment ids, provenance, the settled-season episode sets or the detection cache. This covers records already imported into a 12.0 database and completed modes that found no segments. An adopted record carries the current hash and follows normal invalidation; missing or reset records and unrecognized or empty hashes are never adopted. Releases that did not record Chromaprint availability stay eligible for analysis rather than inventing that state.

Adoption of Chromaprint-capable modes requires the audio-selection settings introduced in 12.0 to keep their defaults, and the 12.0 credits legacy opt-in, the recap cold-open option or active subtitle detection blocks adoption for its mode. The pre-.24 formats omit the snapping-offset option, so enabling it blocks adoption from them. Credits and Preview hashes from .22 and .23 are never adopted: they omit the minimum shared-region duration and the derived-preview option, and today's defaults cannot prove the values those releases used. Those modes stay eligible for analysis even when their settings are at the defaults, so lowering the credits minimum or disabling derived previews still takes effect. Introduction, Recap and Commercial stay eligible for adoption from the older formats. Changes to settings in the 10.11 hash or to the season action still require analysis. The old Chromaprint-availability value is kept, so gaining Chromaprint still reopens a negative result while a failed capability probe does not discard a successful one. Both 1.10.11.24 credits analyzer choices are recognized. Adopted results keep their older detection behavior until an explicit rescan or another normal invalidation; adoption does not claim the newer algorithms produced them.
